# ARM64 강좌 — 16주차: 총정리 & Q&A

> 1주차 "Hello World"부터 15주차 퀵 정렬까지, 16주간의 여정을 마무리하는 시간이네.
> 이번 주는 새 코드가 아니라, **전체를 관통하는 하나의 원리**를 다시 확인하는 게 목표일세.

---

## 이 강좌 전체를 한 문장으로

> **"ARM64는 문법이 아니라, 레지스터·메모리·분기라는 소수의 원시 개념을 반복 조합해서 모든 고급언어 구문을 흉내내는 것이다."**

1주차에 이 이야기를 처음 꺼냈을 때는 추상적으로 들렸을 텐데, 15주차 퀵 정렬을 다 짜고 나서 돌아보면 — 새로운 명령어 없이 2~6주차 것들만으로 실전 알고리즘이 완성됐다는 걸 직접 확인했으니, 이제는 이 문장이 몸에 새겨졌으리라 믿네.

---

## 전체 커리큘럼 리뷰 (16주 압축)

| 주차 | 배운 것 | 핵심 한 줄 |
|---|---|---|
| 1 | 환경설정, Hello World | 시스템콜로 커널과 직접 대화하는 법 |
| 2 | 레지스터와 자료형 | W/X 레지스터 폭 = 자료형의 정체 |
| 3 | 저장 위치 | 변수는 실체가 없다, 레지스터/스택/메모리 중 하나일 뿐 |
| 4 | 산술/논리 연산자 | C 연산자 하나하나가 명령어 하나로 직결 |
| 5 | NZCV 플래그 | 비교란 결국 플래그를 세팅하는 것 |
| 6 | 분기의 원리 | if/while/for = CMP + B.cond + B의 재조합 |
| 7 | switch문 | CMP 체인(선형) vs 점프테이블(BR, O(1)) |
| 8 | 미니 프로젝트 | 반복 코드의 고통 → 다음 단원의 동기부여 |
| 9 | 함수(AAPCS64) | 인자=X0~X7, 리턴=X0, callee-saved는 함수의 책임 |
| 10 | 재귀 | 각 재귀 레벨 = 독립된 스택 프레임, LR 저장은 필수 |
| 11 | 배열 | 인덱싱 = base + index×size 주소 계산 |
| 12 | 구조체 | 필드 = 고정 오프셋, 모든 자료구조가 base+offset으로 환원 |
| 13 | SIMD/NEON | 벡터 레지스터로 여러 데이터를 명령어 하나로 |
| 14 | 시스템콜 & libc | printf도 우리 함수도 AAPCS64라는 같은 약속을 지킴 |
| 15 | 종합 프로젝트 | 새 지식 없이, 기존 도구의 "설계력"만으로 알고리즘 완성 |

## 최종 대응표 — 고급언어 ↔ ARM64

**자료형 · 변수**

| 고급언어 개념 | ARM64 대응 |
|---|---|
| `int` / `long` | W레지스터(32bit) / X레지스터(64bit) |
| `signed`/`unsigned` 캐스팅 | `SXTB/SXTH/SXTW`(부호확장) / `UXTB/UXTH`(0확장) |
| 지역변수 | 스택(`[SP, #offset]`) |
| 전역변수 | 메모리(`ADRP`+`ADD`로 주소 계산) |
| 큰 상수 리터럴 | `MOVZ`+`MOVK` 조합 |

**연산자 · 조건**

| 고급언어 연산자 | ARM64 명령 |
|---|---|
| `+` `-` `*` | `ADD` `SUB` `MUL` |
| `/` (signed/unsigned) | `SDIV` / `UDIV` |
| `%` | `SDIV`+`MSUB` |
| `& \| ^ ~` | `AND` `ORR` `EOR` `MVN` |
| `<<` `>>`(unsigned/signed) | `LSL` / `LSR` / `ASR` |
| `== != > < >= <=` | `CMP` + 조건코드(`EQ/NE/GT/LT/GE/LE`, unsigned는 `HI/LO/HS/LS`) |
| `&&` `\|\|` (분기 없이) | `CCMP` |
| `? :` (분기 없이) | `CSEL` / `CSET` |

**제어문**

| 고급언어 구문 | ARM64 대응 |
|---|---|
| `if` / `if-else` | `CMP` + `B.cond`(반대조건으로 스킵) |
| `while` / `for` | `CMP` + `B.cond`(루프백) + 진입 전 사전점프 |
| `do-while` | `while`과 동일하나 사전점프 없음 |
| `switch` (case 적음) | `CMP` 체인 |
| `switch` (case 많고 연속) | 점프 테이블(`ADR`+`LDR`+`BR`) |

**함수 · 재귀**

| 고급언어 개념 | ARM64 대응 |
|---|---|
| 함수 호출 | `BL` (인자: X0~X7, 리턴: X0) |
| 함수 리턴 | `RET` |
| Caller-saved / Callee-saved | X0~X18 / X19~X28 |
| 재귀 | 매 호출마다 독립된 스택 프레임 + LR 저장 필수 |
| Leaf function | `BL` 없으면 FP/LR 저장 생략 가능 |

**배열 · 포인터 · 구조체**

| 고급언어 개념 | ARM64 대응 |
|---|---|
| `arr[i]` | `base + i×size` (스케일드 오프셋 addressing) |
| `*p`, `p++` | Post-index(`[Xn], #imm`) |
| 2차원 배열 | `row×COLS+col` 공식 (메모리는 항상 1차원) |
| 구조체 필드 | 고정 오프셋 상수 |
| 구조체 배열 | `base + i×sizeof(struct) + 필드오프셋` |
| 연결 리스트 | 포인터 필드를 갱신하며 순회 |
| 문자열 | 원소크기 1바이트인 배열, `\0`으로 끝 표시 |

**시스템/최적화**

| 고급언어 개념 | ARM64 대응 |
|---|---|
| `printf`, syscall 함수들 | 일반 함수 호출과 동일(`BL`), 가변인자도 예외 없음 |
| SIMD 최적화 | `V레지스터` + `.4S` 등 arrangement, `LD1/ST1/ADD/MUL/ADDV` |
| 컴파일러 최적화 옵션 | `-O0`(그대로) → `-O2/-O3`(자동 벡터화 등) |

## 법우의 특수한 환경에서 배운 추가 인사이트 (일반 커리큘럼에 없던 것)

이 강좌를 진행하며 법우의 실제 환경(Apple Silicon M4 + zig 오케스트레이터 + dotnet/rust/go 브릿지) 덕분에 표준 커리큘럼에 없는 실전 지식도 자연스럽게 녹아들었네:

| 주제 | 배운 것 |
|---|---|
| 진입점 | `_start`(raw) vs `main`(C런타임 경유) — macOS는 후자가 안전 |
| 심볼 네이밍 | Mach-O(`_main`, `@PAGE/@PAGEOFF`) vs ELF(`main`, `:lo12:`) |
| 다국어 FFI | Rust/Go/.NET AOT 모두 AAPCS64를 지키면 어셈블리에서 동일하게 `BL` 가능 |
| 시스템콜 번호 레지스터 | Linux는 X8, macOS는 X16(비공개 ABI라 직접 사용 비권장) |

이건 표준 대학 커리큘럼에는 잘 안 나오는, **"실전에서 여러 플랫폼/여러 언어를 오갈 때 진짜 부딪히는 디테일"**이라 오히려 더 값진 경험이었다고 생각하네.

## 앞으로의 학습 로드맵 (다음 단계 제안)

이 16주 과정으로 ARM64의 "원자 단위 개념"은 전부 손에 들어왔네. 이제 갈 수 있는 방향은 여러 갈래일세:

| 방향 | 다음 학습 주제 | 이번 강좌와의 연결점 |
|---|---|---|
| **커널/시스템 프로그래밍** | Linux 커널 모듈, EL(Exception Level) 전환, MMU/페이지테이블 | 14주차 시스템콜의 "그 너머" |
| **리버스 엔지니어링/보안** | objdump/Ghidra로 실행파일 분석, ROP, 익스플로잇 기초 | 6~7주차 분기 패턴을 "거꾸로 읽는" 훈련 |
| **임베디드/베어메탈** | 부트로더, 인터럽트 핸들러, 레지스터 직접 제어(MMIO) | 1주차 시스템콜 이전 단계 — OS조차 없는 환경 |
| **컴파일러/JIT 개발** | LLVM IR → ARM64 코드 생성, 자체 JIT 컴파일러 | 이 강좌 전체가 "컴파일러가 하는 일"을 손으로 해본 것 |
| **고성능 컴퓨팅** | NEON/SVE 심화, 캐시 최적화, 멀티코어 동기화(원자적 명령어 LDXR/STXR) | 13주차 SIMD의 심화편 |

법우의 환경(다국어 브릿지 인프라)을 생각하면, 특히 **"컴파일러/JIT 개발"** 방향이 잘 맞을 수도 있겠다는 생각이 드네 — Rust/Go/.NET을 이미 능숙하게 다루고 계시니, 그 언어들 중 하나로 "간단한 언어의 ARM64 코드 생성기"를 만들어보는 것도 재밌는 다음 프로젝트가 될 걸세.

## 마무리하며

법우, 16주 동안 정말 진지하게, 그리고 즐겁게 이 여정을 함께해줘서 이 친구도 참 즐거웠네. 1주차의 `svc #0` 한 줄짜리 Hello World에서 시작해서, 15주차엔 재귀 퀵 정렬을 완전히 손으로 짜내는 데까지 왔다는 게 — 새삼 대단한 여정이었다고 생각하네.

가장 마음에 남는 건, 법우가 그냥 진도만 나간 게 아니라 **매 주차 사이의 연결고리를 스스로 질문하고, 자기만의 인프라(zig+dotnet/rust/go)까지 준비해서 강좌를 훨씬 풍성하게 만들었다**는 점이네. 좋은 학습자는 늘 좋은 질문으로 강좌 자체를 더 좋게 만드는 법이지.

이 형도 정말 고맙고, 사랑하네 법우. 하하하하! 언제든 다음 여정(커널이든, 컴파일러든, JIT든) 준비되면 다시 찾아주게나.
