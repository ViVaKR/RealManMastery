# ARM64 예제 코드 — 1~2주차

> 표기: 왼쪽은 C 코드(익숙한 감각용), 오른쪽은 ARM64 어셈블리(GNU AS 문법, AAPCS64 기준).
> 빌드: `as -o out.o file.s && ld -o out out.o` 또는 `gcc -nostdlib -o out file.s` (환경에 따라 조정)

---

## 1주차 — Hello World (시스템 콜 직접 호출)

리눅스 AArch64는 시스템 콜 번호를 **X8**에 넣고 `SVC #0`으로 커널을 호출하네.
write(1) = 시스템콜 64번, exit(1) = 시스템콜 93번.

**C 코드 (참고용, libc 사용)**
```c
#include <unistd.h>

int main(void) {
    write(1, "Hello, ARM64!\n", 14);
    return 0;
}
```

**ARM64 어셈블리 (시스템 콜 직접 사용)**
```asm
.global _start
.text

_start:
    // write(1, msg, 14)
    mov     x0, #1          // fd = stdout
    adr     x1, msg         // buf 주소
    mov     x2, #14         // 길이
    mov     x8, #64         // syscall number: write
    svc     #0

    // exit(0)
    mov     x0, #0          // exit code
    mov     x8, #93         // syscall number: exit
    svc     #0

.data

msg: .ascii  "Hello, ARM64!\n"

```

**포인트**
- `_start`가 진입점 (libc 없이 직접 커널 호출)
- `adr`는 근접 주소(±1MB)를 레지스터에 로드하는 명령. 먼 주소는 3주차에 배울 `adrp+add` 사용
- 리턴값 개념이 없고, `exit` 시스템콜을 직접 불러야 프로세스가 종료됨

## 2주차 — 레지스터 폭과 자료형 대응

### 예제 1: 정수 크기별 저장/로드 (int8 ~ int64)

**C 코드**
```c
#include <stdint.h>

int main(void) {
    int8_t  a = -5;
    int16_t b = 1000;
    int32_t c = 100000;
    int64_t d = 10000000000;
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _start

_start:
    // int8_t a = -5;
    mov     w0, #-5
    strb    w0, [sp, #-16]!     // 1바이트 저장, 스택 8바이트 정렬 유지 위해 -16

    // int16_t b = 1000;
    mov     w1, #1000
    strh    w1, [sp, #-16]!

    // int32_t c = 100000;
    mov     w2, #100000
    str     w2, [sp, #-16]!     // W레지스터 = 32비트

    // int64_t d = 10000000000;
    mov     x3, #10000000000    // X레지스터 = 64비트
    str     x3, [sp, #-16]!

    // exit(0)
    mov     x0, #0
    mov     x8, #93
    svc     #0
```

**포인트 — "자료형 = 크기와 해석"**
| C 자료형 | 크기 | 저장 명령 | 레지스터 |
|---|---|---|---|
| `int8_t` | 1바이트 | `strb` | W (하위 8비트만 사용) |
| `int16_t` | 2바이트 | `strh` | W (하위 16비트만 사용) |
| `int32_t` | 4바이트 | `str` (W) | W0~W30 |
| `int64_t` | 8바이트 | `str` (X) | X0~X30 |

같은 물리 레지스터라도 `W0`으로 쓰면 하위 32비트, `X0`으로 쓰면 전체 64비트를 의미하네. 즉 "레지스터가 자료형을 아는 것이 아니라, 명령어와 레지스터 이름이 자료형의 해석을 결정한다"는 게 핵심이네.

### 예제 2: 부호 확장 (signed vs unsigned)

**C 코드**
```c
int8_t  a = -5;
int32_t b = (int32_t)a;   // 부호 확장

uint8_t c = 250;
uint32_t d = (uint32_t)c; // 0 확장
```

**ARM64 어셈블리**
```asm
    mov     w0, #-5
    sxtb    w1, w0          // signed extend byte -> w1 = -5 (32bit)

    mov     w2, #250
    uxtb    w3, w2          // unsigned extend byte -> w3 = 250 (32bit, 0으로 채움)
```

**포인트**
- `SXTB/SXTH/SXTW`: 부호 확장 (음수 비트를 그대로 채움)
- `UXTB/UXTH`: 0 확장 (상위 비트를 0으로 채움)
- 고급언어의 `signed`/`unsigned` 캐스팅이 여기서 명시적 명령으로 드러남

### 예제 3: 즉치값 로딩 패턴 (MOVZ/MOVK)

**C 코드**
```c
uint64_t addr = 0x1234567890ABCDEF;
```

**ARM64 어셈블리**
```asm
    movz    x0, #0xCDEF                  // 하위 16비트, 나머지 0으로 초기화
    movk    x0, #0x9078, lsl #16         // 다음 16비트 삽입 (기존 값 유지)
    movk    x0, #0x5634, lsl #32
    movk    x0, #0x1234, lsl #48
```

**포인트**
- ARM64 명령어는 고정 32비트 길이라 64비트 즉치값을 한 번에 넣을 수 없음
- `MOVZ`(0으로 초기화 후 삽입) → `MOVK`(기존 값 유지하며 16비트씩 삽입) 조합으로 완성
- 큰 상수를 만드는 표준 패턴이니 꼭 손에 익혀둘 것
