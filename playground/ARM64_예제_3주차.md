# ARM64 예제 코드 — 3주차: 저장 위치 (레지스터 / 스택 / 메모리)

> **변경사항 반영**: 이제부터 진입점은 `_start`(raw syscall) 대신 `main`을 쓰고,
> 출력은 syscall 대신 법우가 만든 **.NET AOT / Go / Rust 브릿지 라이브러리**를 `bl`로 호출하는 방식으로 진행하네.
>
> 파일은 `src/` 하위 어딘가(`.S`)에 두면 `build.zig`가 자동으로 찾아서 링크하네.

---

## 진입점 및 심볼 네이밍 — 먼저 짚고 갈 것

| 플랫폼 | 오브젝트 포맷 | `main` 심볼 | 브릿지 함수 호출 예 |
|---|---|---|---|
| macOS (Apple Silicon, M4) | Mach-O | `.global _main` | `bl _calc_sum` |
| Linux aarch64 | ELF | `.global main` | `bl calc_sum` |

이 문서의 예제는 **macOS(Mach-O) 문법 기준**으로 작성하네 (M4가 주 타겟이라 하셨으니). Linux로 옮길 땐 언더스코어(`_`)를 떼고, `adrp`의 `@PAGE`/`@PAGEOFF`도 GNU 문법(`:lo12:`)으로 바꿔야 하는데, 이 부분은 아래 예제 2에서 짚어두겠네.

### 공통 뼈대 (앞으로 계속 재사용할 템플릿)

```asm
_main:
    stp     x29, x30, [sp, #-16]!   // 프롤로그: FP/LR 저장 (스택 16바이트 정렬 유지)
    mov     x29, sp                 // 프레임 포인터 설정

    // ... 본문 ...

    mov     w0, #0                  // 리턴값 0 (exit code 아님! main의 리턴값)
    ldp     x29, x30, [sp], #16     // 에필로그: FP/LR 복원
    ret                             // C 런타임으로 복귀 → 런타임이 알아서 exit() 처리
```

**포인트 — 왜 `svc`가 사라졌나?**
`main`은 C 런타임(crt)이 `bl main` 형태로 호출해준 것이라, 여기서 `ret`으로 복귀하면 **런타임이 리턴값을 받아 알아서 `exit()`을 호출**해주네. 1주차의 `_start` 방식과 달리 우리가 직접 시스템 콜을 낼 필요가 없어진 게 핵심 차이일세.

**포인트 — 왜 스택 프레임이 필수가 됐나?**
`bl 브릿지함수`를 호출하는 순간 **X30(LR)이 그 함수의 리턴 주소로 덮어써짐**. `main`으로 돌아가려면 우리 자신의 리턴 주소(X30)를 먼저 스택에 저장해둬야 하네. 즉, **다른 함수를 `bl`로 부르는 순간 그 함수는 더 이상 "leaf function"이 아니고, 반드시 X29/X30을 저장·복원해야 함** — 이게 3주차 스택 개념의 실전 이유라네.

## 예제 1 — 지역변수는 스택에 (Rust `welcome_rust` 호출)

**C 등가 코드 (extern 선언으로 브릿지를 부른다고 가정)**
```c
extern void welcome_rust(unsigned long num);

int main(void) {
    unsigned long num = 42;   // 지역변수
    welcome_rust(num);
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _welcome_rust

_main:
    stp     x29, x30, [sp, #-32]!   // FP/LR(16) + 지역변수 공간(16) = 32바이트 프레임
    mov     x29, sp

    mov     x0, #42
    str     x0, [sp, #16] // "지역변수 num"을 스택에 저장 (x29+16 위치)

    ldr     x0, [sp, #16] // 다시 로드해서 첫 번째 인자(x0)로 전달
    bl      _welcome_rust // Rust: 하하하 인사말 + 값 출력

    mov     w0, #0
    ldp     x29, x30, [sp], #32
    ret
```

**포인트**
- `num`을 레지스터에 그냥 들고 있어도 되지만, 일부러 스택에 내렸다 올려서 **"지역변수 = SP 기준 오프셋 메모리"**라는 개념을 눈으로 확인시키는 예제네
- 프레임 크기 32바이트 = FP/LR 저장용 16 + 지역변수용 16 (정렬 유지 위해 8의 배수가 아니라 **16의 배수**로 맞춤 — AAPCS64 규칙)
- `welcome_rust(u64 num)`이 `x0` 하나만 받으므로 64비트 레지스터 `x0` 사용 (32비트였다면 `w0`)

## 예제 2 — 전역변수는 메모리에 (Go `go_print_int` 호출)

**C 등가 코드**
```c
extern void go_print_int(int v);

static int global_counter = 100;   // 전역변수

int main(void) {
    global_counter += 1;
    go_print_int(global_counter);
    return 0;
}
```

**ARM64 어셈블리 (macOS Mach-O 문법)**
```asm
    .data
    .align  2
global_counter:
    .word   100

    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    adrp    x1, global_counter@PAGE      // 4KB 페이지 단위 주소 로드
    add     x1, x1, global_counter@PAGEOFF  // 페이지 내 오프셋 더해서 완전한 주소 완성

    ldr     w0, [x1]                     // global_counter 값 로드
    add     w0, w0, #1                   // +1
    str     w0, [x1]                     // 다시 저장 (메모리 갱신)

    ldr     w0, [x1]                     // 갱신된 값을 다시 로드해서 인자로
    bl      _go_print_int

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트 — 전역변수 주소 계산은 2단계**
1. `ADRP`로 PC 기준 **4KB 페이지 단위** 주소를 구함 (±4GB 범위 커버 가능)
2. `ADD`(또는 `LDR`)로 **페이지 내 오프셋**을 더해 정확한 주소 완성

**⚠️ 플랫폼 문법 차이 — 여기가 M4/Linux 갈리는 지점**
| 플랫폼 | 문법 |
|---|---|
| macOS (Mach-O) | `adrp x1, global_counter@PAGE` / `add x1, x1, global_counter@PAGEOFF` |
| Linux (ELF, GNU as) | `adrp x1, global_counter` / `add x1, x1, :lo12:global_counter` |

동일한 개념(2단계 주소 계산)이지만 어셈블러 문법이 다르니, Linux로 포팅할 때 이 두 줄만 바꿔주면 되네.

## 예제 3 — 레지스터만으로 충분한 경우 (Rust `calc_sum` 호출)

**C 등가 코드**
```c
extern void calc_sum(unsigned long a, unsigned long b);

int main(void) {
    calc_sum(10, 20);   // 지역변수 없이 바로 레지스터로 전달
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _calc_sum

_main:
    stp     x29, x30, [sp, #-16]!   // bl 한 번이라도 쓰면 이 저장은 여전히 필수!
    mov     x29, sp

    mov     x0, #10                 // 첫 번째 인자
    mov     x1, #20                 // 두 번째 인자
    bl      _calc_sum               // Rust: "10 + 20 = 30" 출력

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트**
- 값을 저장할 지역변수가 없으니 스택 공간은 안 늘어남 (프레임 16바이트 = FP/LR 저장분뿐)
- 하지만 **`bl`을 한 번이라도 쓰면 스택 프레임(FP/LR 저장)은 생략 불가** — "레지스터만 쓰는 것"과 "스택 프레임이 없는 것"은 별개 문제라는 걸 이 예제로 구분해서 보여주는 것이 포인트

## 3주차 정리 — 저장 위치 3분류 요약표

| 저장 위치 | 언제 쓰나 | 이번 주 예제 |
|---|---|---|
| 레지스터 | 값이 잠깐 쓰이고 바로 다른 함수 호출에 소비될 때 | 예제 3 (calc_sum 인자) |
| 스택 (SP/FP 기준 오프셋) | 함수 내에서만 쓰이는 지역변수, 호출 후에도 값 유지 필요할 때 | 예제 1 (welcome_rust) |
| 메모리 (전역, ADRP+ADD) | 함수 호출을 넘어, 프로그램 전체에서 공유되는 값 | 예제 2 (go_print_int) |
