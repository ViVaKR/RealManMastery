# ARM64 예제 코드 — 6주차: 분기의 원리 (if / while / for)

> **이번 주 핵심 명제**: 고급언어의 `if`, `while`, `for`는 문법이 아니라
> **`CMP`(비교) + `B.cond`(조건분기) + `B`(무조건분기)**, 이 세 조각의 조합일 뿐이네.
> 5주차에서 배운 조건 코드(EQ/NE/GT...)가 여기서 `B.cond`의 `cond` 자리에 그대로 들어가네.

---

## 예제 1 — if / if-else

**C 등가 코드**
```c
extern void go_print_int(int v);

int main(void) {
    int score = 75;
    int result;

    if (score >= 60) {
        result = 1;   // pass
    } else {
        result = 0;   // fail
    }

    go_print_int(result);
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    mov     w19, #75            // score

    cmp     w19, #60
    b.lt    else_branch          // score < 60 이면 else로 점프 (조건의 "반대"로 분기하는 게 관용 패턴!)

    mov     w20, #1              // if 블록: result = 1
    b       end_if

else_branch:
    mov     w20, #0              // else 블록: result = 0

end_if:
    mov     w0, w20
    bl      _go_print_int

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트 — 왜 `b.lt`(반대 조건)로 분기하나**
C 코드는 `score >= 60`이 **참일 때** if 블록을 실행하지만, 어셈블리에서는 보통 **조건의 반대(`< 60`)가 참일 때 else로 건너뛰는 식**으로 짜는 게 관용 패턴이네. "만족하면 아래로 쭉 이어서 실행, 불만족하면 점프해서 건너뛴다"는 구조가 코드 흐름을 더 선형적으로 만들어주기 때문. 컴파일러도 실제로 이렇게 뒤집어서 컴파일하네.

## 예제 2 — while 루프 (1부터 N까지 합)

**C 등가 코드**
```c
extern void go_print_int(int v);

int main(void) {
    int i = 1, n = 5, sum = 0;

    while (i <= n) {
        sum += i;
        i++;
    }

    go_print_int(sum);   // 15
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    mov     w19, #1              // i = 1
    mov     w20, #5              // n = 5
    mov     w21, #0              // sum = 0

    b       while_cond            // 관용 패턴: 본문보다 조건 체크를 먼저 하도록 점프

while_body:
    add     w21, w21, w19         // sum += i
    add     w19, w19, #1          // i++

while_cond:
    cmp     w19, w20
    b.le    while_body            // i <= n 이면 본문으로 다시 (루프백)

    mov     w0, w21
    bl      _go_print_int          // 15 출력

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트 — "조건을 맨 아래로 옮기는" 최적화 패턴**
직관적으로 짜면 `while_cond`가 맨 위에 있고 매 반복마다 `b while_cond`로 다시 위로 뛰어야 할 것 같은데, 위 코드는 **처음 한 번만 `b while_cond`로 아래 점프**하고, 이후엔 루프 본문 끝에서 조건 체크 후 **`b.le`로 위로 되돌아가는 구조**네. 이렇게 하면 **매 반복마다 무조건분기(B)가 아니라 조건분기(B.cond) 하나만 실행**되어 명령 수가 줄어듦 — 컴파일러가 `-O1` 이상에서 항상 이렇게 변환하는 표준 최적화 패턴이니 익혀두면 좋네.

## 예제 3 — for 루프 (배열 없이 카운터만)

**C 등가 코드**
```c
extern void go_print_int(int v);

int main(void) {
    for (int i = 0; i < 3; i++) {
        go_print_int(i);
    }
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    mov     w19, #0              // for (int i = 0; ...  → 초기화
    b       for_cond

for_body:
    mov     w0, w19
    bl      _go_print_int         // go_print_int(i)  ※ bl 호출은 w19(callee-saved)를 보존해주므로 안전

    add     w19, w19, #1          // i++

for_cond:
    cmp     w19, #3
    b.lt    for_body               // i < 3 이면 계속

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트**
- `for (초기화; 조건; 증감)`은 사실 **while과 어셈블리 구조가 동일**하고, 차이는 "증감식이 루프 본문 끝에 붙는다"는 관례뿐이네. 즉 **for와 while은 어셈블리 레벨에서 구분이 없음** — 이게 6주차 핵심 명제의 좋은 증거일세
- 루프 안에서 `bl _go_print_int`를 호출하는데도 `w19`(카운터)가 안전한 이유: **X19~X28은 callee-saved라서, 브릿지 함수(Go 런타임)가 내부적으로 뭘 하든 호출 후 값이 그대로 보존된다는 게 AAPCS64 규약으로 보장됨** (4주차에서 예고했던 내용이 여기서 실전으로 쓰이는 것)

## 예제 4 — do-while (최소 1회 실행 보장)

**C 등가 코드**
```c
extern void go_print_int(int v);

int main(void) {
    int i = 10;

    do {
        go_print_int(i);
        i++;
    } while (i < 10);   // 조건이 처음부터 거짓이어도 1회는 실행됨

    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    mov     w19, #10             // i = 10

do_body:
    mov     w0, w19
    bl      _go_print_int         // 조건 체크 없이 무조건 먼저 실행!

    add     w19, w19, #1          // i++

    cmp     w19, #10
    b.lt    do_body                // 조건 참이면 반복

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트 — while과의 유일한 구조적 차이**
`do-while`은 예제 2의 `while`과 비교하면 **맨 처음의 `b while_cond`(조건으로 먼저 점프하는 코드)가 아예 없음**. 그래서 무조건 본문을 한 번은 실행하고 나서야 조건을 체크하게 되는 것이지. **"본문 진입 전에 조건으로 미리 점프하느냐, 안 하느냐"** — 이 한 줄 차이가 `while`과 `do-while`의 전부라는 걸 확인할 수 있네.

## 6주차 정리 — 왜 if/while/for/do-while이 "같은 원리"인가

| 고급언어 구문 | 필요한 조각 | 진입 전 사전 점프? |
|---|---|---|
| `if` / `if-else` | `CMP` + `B.cond`(반대조건) + `B`(if 끝에서 스킵) | 불필요 |
| `while` | `CMP` + `B.cond`(루프백) + 진입 전 `B`(조건으로 점프) | **필요** |
| `for` | while과 동일 구조 (증감식 위치만 다름) | **필요** |
| `do-while` | `CMP` + `B.cond`(루프백)만 | **불필요** |

결국 이 넷의 차이는:
1. 분기가 **"건너뛰는 방향"**(if: 아래로 스킵 / loop: 위로 되돌아감)
2. **"조건 체크를 본문 앞에 먼저 하느냐, 본문 뒤에서 하느냐"**

이 두 가지 뿐이고, 나머지는 전부 `CMP` + `B.cond` + `B`라는 동일한 원자 단위의 재조합이라는 게 이번 주의 결론이네.
