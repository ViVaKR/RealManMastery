# ARM64 예제 코드 — 5주차: 조건 플래그(NZCV)와 비교 명령

> 이번 주부터가 사실상 "분기(6주차)"로 가는 다리 역할이네.
> **분기 없이도 조건을 처리하는 법(CSEL/CSET)**을 먼저 익혀두면, 다음 주 `B.cond`가 왜 필요한지도 더 선명해질 걸세.

---

## NZCV란 무엇인가 — 먼저 개념부터

ARM64에는 `PSTATE`라는 상태 레지스터 안에 4개의 조건 플래그 비트가 있네:

| 플래그 | 의미 | 언제 1이 되나 |
|---|---|---|
| **N** (Negative) | 결과가 음수 | 결과의 최상위 비트(부호비트)가 1일 때 |
| **Z** (Zero) | 결과가 0 | 연산 결과가 정확히 0일 때 |
| **C** (Carry) | 자리올림/빌림 발생 | unsigned 덧셈에서 오버플로우, 또는 뺄셈에서 빌림이 없을 때 |
| **V** (oVerflow) | signed 오버플로우 | 부호있는 연산 결과가 표현 범위를 벗어났을 때 |

이 플래그들은 **`S`가 붙은 명령**(`ADDS`, `SUBS`) 또는 **`CMP`/`CMN`/`TST`** 같은 비교 전용 명령을 실행할 때만 갱신되네. 일반 `ADD`, `SUB`는 플래그를 안 건드림.

## 예제 1 — CMP와 조건부 저장 (CSET) — 분기 없이 bool 만들기

**C 등가 코드**
```c
extern void go_print_int(int v);

int main(void) {
    int a = 17, b = 5;
    int is_greater = (a > b);   // 1 또는 0
    go_print_int(is_greater);
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    mov     w0, #17             // a
    mov     w1, #5              // b

    cmp     w0, w1              // 내부적으로 SUBS wzr, w0, w1 과 동일 (결과 버리고 플래그만 세팅)
    cset    w0, gt               // NZCV가 "gt(초과)" 조건 만족하면 w0=1, 아니면 w0=0

    bl      _go_print_int

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트**
- `CMP Wn, Wm`은 사실 `SUBS WZR, Wn, Wm` (결과는 버리는 레지스터 `WZR`에, 플래그만 세팅)의 별칭(alias)이네
- `CSET Wd, cond`: 조건이 참이면 `Wd = 1`, 거짓이면 `Wd = 0` — **분기(branch) 없이 조건 결과를 값으로 만드는 명령**
- 6주차에서 배울 `if`문은 사실 이 자리에 `B.cond`를 넣으면 되는 것 — 이번 주가 그 준비 단계임

## 예제 2 — 조건 코드 총정리 (EQ/NE/GT/LT/GE/LE...)

**C 등가 코드**
```c
extern void go_print_int(int v);

int main(void) {
    int a = 10, b = 10;
    go_print_int(a == b);   // 1
    go_print_int(a != b);   // 0
    go_print_int(a >= b);   // 1
    go_print_int(a <= b);   // 1
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    mov     w19, #10            // a
    mov     w20, #10            // b
    cmp     w19, w20            // 플래그 세팅 (한 번만 하면 아래서 계속 재사용 가능)

    cset    w0, eq              // a == b
    bl      _go_print_int

    cset    w0, ne              // a != b
    bl      _go_print_int

    cset    w0, ge              // a >= b (signed)
    bl      _go_print_int

    cset    w0, le              // a <= b (signed)
    bl      _go_print_int

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**⚠️ 주의**: `cmp` 이후 `bl _go_print_int`를 호출하면 **NZCV 플래그가 함수 호출 과정에서 보존된다는 보장이 없음**(브릿지 라이브러리 내부에서 자기 연산을 하면 플래그가 바뀜). 위 예제는 각 `cset` 직전에 매번 다시 `cmp`를 해야 안전하지만, 지면상 한 번만 표기했네. **실전 코드에서는 매 `cset`/`b.cond` 앞에 `cmp`를 다시 해주는 게 안전**하다는 점 꼭 기억해두게.

**조건 코드 총정리표**

| 조건 | 의미 (signed) | 의미 (unsigned) | 플래그 조합 |
|---|---|---|---|
| `EQ` | == | == | Z=1 |
| `NE` | != | != | Z=0 |
| `GT` | > | (HI 사용) | Z=0 and N=V |
| `GE` | >= | (HS 사용) | N=V |
| `LT` | < | (LO 사용) | N≠V |
| `LE` | <= | (LS 사용) | Z=1 or N≠V |
| `HI` | (GT 사용) | > | C=1 and Z=0 |
| `LO` | (LT 사용) | < | C=0 |
| `HS` | (GE 사용) | >= | C=1 |
| `LS` | (LE 사용) | <= | C=0 or Z=1 |

**포인트**: signed 비교엔 `GT/GE/LT/LE`, unsigned 비교엔 `HI/HS/LO/LS`를 쓰네. 헷갈리면 안 되는 게, **`int`끼리 비교는 무조건 signed 조건 코드**를 쓰고, `unsigned int`끼리 비교는 unsigned 조건 코드를 써야 하네 — 이것도 2주차 "자료형=해석"이 여기서 다시 등장하는 셈.

## 예제 3 — CCMP로 복합 조건 (`&&`, `||`) 처리

**C 등가 코드**
```c
extern void go_print_int(int v);

int main(void) {
    int age = 25;
    int has_ticket = 1;

    // age >= 18 && has_ticket == 1
    int can_enter = (age >= 18) && (has_ticket == 1);
    go_print_int(can_enter);
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    mov     w0, #25             // age
    mov     w1, #1              // has_ticket

    cmp     w0, #18                      // age >= 18 ?
    ccmp    w1, #1, #0b0000, ge          // 첫 조건이 참(ge)일 때만 두 번째 CMP 실행
                                          // 첫 조건이 거짓이면 NZCV를 강제로 #0b0000(모두 0, 즉 "거짓" 상태)로 세팅
    cset    w0, eq                       // 최종 결과: 두 조건 다 만족해야 eq

    bl      _go_print_int

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트**
- `CCMP Wn, #imm, #nzcv, cond`: **cond가 참일 때만** `CMP Wn, #imm`을 실제로 수행하고, **cond가 거짓이면 NZCV를 지정한 값(`#nzcv`)으로 강제 세팅**
- 이게 바로 **단락 평가(short-circuit evaluation)**를 분기 없이 구현하는 방법 — C의 `&&`가 왜 "첫 조건 거짓이면 두 번째는 평가 안 함"인지와 원리가 같음
- 분기(`B.cond`)로 처리할 수도 있지만, 짧은 복합조건은 `CCMP`로 분기 예측 실패(branch misprediction) 비용 없이 처리 가능 — 성능 상 이점

## 예제 4 — 오버플로우/캐리 감지 (V, C 플래그 실전 활용)

**C 등가 코드**
```c
extern void go_print_int(int v);
#include <limits.h>

int main(void) {
    int a = INT_MAX;   // 2147483647
    int b = 1;
    // a + b 는 signed overflow 발생!
    int overflowed = __builtin_add_overflow(a, b, &a); // 개념적 표현
    go_print_int(overflowed);
    return 0;
}
```

**ARM64 어셈블리**
```asm
    .text
    .global _main
    .extern _go_print_int

_main:
    stp     x29, x30, [sp, #-16]!
    mov     x29, sp

    mov     w0, #0x7FFFFFFF     // INT_MAX
    mov     w1, #1

    adds    w2, w0, w1          // ADDS: 덧셈 수행 + 플래그 갱신 (일반 ADD와 달리 S가 붙음)
    cset    w0, vs               // V플래그가 섰으면(overflow set) 1

    bl      _go_print_int        // 결과: 1 (오버플로우 발생!)

    mov     w0, #0
    ldp     x29, x30, [sp], #16
    ret
```

**포인트**
- `ADDS`/`SUBS`처럼 **`S`가 붙은 연산 명령은 계산도 하면서 플래그도 갱신**함 (`CMP`는 계산 결과를 버리는 특수 케이스일 뿐)
- `VS`(oVerflow Set) / `VC`(oVerflow Clear) 조건 코드로 signed 오버플로우를 직접 감지 가능
- C에서는 이런 오버플로우 체크가 `__builtin_add_overflow` 같은 컴파일러 내장 함수로만 가능한데, 어셈블리에서는 플래그를 직접 읽어서 훨씬 저수준으로 확인할 수 있다는 게 이번 예제의 포인트

## 5주차 정리

| 개념 | 명령/문법 | 용도 |
|---|---|---|
| 비교(결과 버림) | `CMP`, `CMN` | `==`, `!=`, `<`, `>` 등 판단용 |
| 비트 테스트 | `TST` | `if (flags & MASK)` 패턴 |
| 조건부 값 생성 | `CSET Wd, cond` | 분기 없이 bool(0/1) 생성 |
| 조건부 선택 | `CSEL Wd, Wn, Wm, cond` | 삼항연산자(`? :`) 분기 없이 구현 (다음 주 미리보기) |
| 복합조건 | `CCMP` | `&&`, `||` 를 분기 없이 처리 |
| 오버플로우 감지 | `ADDS`/`SUBS` + `VS`/`VC` | signed overflow 체크 |
