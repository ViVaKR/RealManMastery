## 세션 1 — 메모리 주소지정과 로드/스토어 (45분)

### 핵심 그림: 레지스터는 책상, 메모리는 서랍장

- 지금까지 `mov`, `add`는 전부 "책상 위(레지스터)"에서만 벌어진 일
- `ldr`(load register), `str`(store register)로 처음 "서랍장(메모리)"을 열고 닫음

### 참조 코드 먼저 — C# 배열

```csharp
int[] arr = { 10, 20, 30, 40, 50 };
int sum = 0;
for (int i = 0; i < arr.Length; i++)
{
    sum += arr[i];
}
Console.WriteLine(sum);   // 150
```

> **연결고리**: "C#에서 `arr[i]`라고 쓰는 순간, 그 밑에서는 배열의 시작 주소에 `i * 4바이트`를 더한 위치로 가서 값을 읽어옵니다. 오늘 이걸 그대로 어셈블리 손으로 해봅니다."

### 따라 만들기 — ASM 배열 순회

```asm
.data
.align 3
arr: .word 10, 20, 30, 40, 50
arr_len: .word 5

.global _main
.align 4

_main:
    adrp x0, arr@PAGE
    add x0, x0, arr@PAGEOFF   // x0 = 배열 시작 주소

    mov x1, #0                  // sum
    mov x2, #0                  // i

_loop:
    cmp x2, #5
    b.ge _loop_end

    ldr w3, [x0, x2, lsl #2]    // arr[i] 로드 — 주소 = base + i*4
    add w1, w1, w3               // sum += arr[i]
    add x2, x2, #1               // i++
    b _loop

_loop_end:
    // w1 에 결과(150) 담김
    ...
```

> **대응점 짚기 (반드시 화면에 두 코드 나란히)**: "`arr[i]`라는 C# 한 줄이, ASM에서는 `ldr w3, [x0, x2, lsl #2]` 이 한 줄로 대응됩니다. `lsl #2`가 정확히 `i * 4바이트`(int 크기)를 계산해주는 부분이에요. 2부에서 배운 `add x0, x1, x2, lsl #2`를 기억하시나요? 그게 여기서 이렇게 쓰입니다."

### 주소지정 방식 3종 세트

```asm
ldr w0, [x1]                // 1. 기본 — x1이 가리키는 주소
ldr w0, [x1, #8]             // 2. 오프셋 — x1 + 8 위치
ldr w0, [x1, x2, lsl #2]      // 3. 인덱스+스케일 — 배열 접근의 정석
```

> **실전 팁**: "이 세 가지만 익숙해지면 대부분의 메모리 접근 코드는 다 읽힙니다. C# 개발자분들껜 이게 딱 `array[i]`, `struct.field`, 포인터 연산 세 가지가 어셈블리로 내려온 모습이라고 생각하시면 돼요."

## 세션 2 — NEON/SIMD 맛보기: lane specifier와 레인 인덱싱 (50분)

여기부터는 준님이 지금 실전에서 직접 파고 계신 영역입니다. C#으로 깔끔하게 대응시키기보다, **"왜 이게 필요한가"부터 하드웨어 관점으로 설득**하는 방식으로 갑니다.

### 왜 NEON인가 — 동기부여 먼저

> "지금까지 배운 명령어들은 레지스터 하나에 값 하나씩 넣고 계산했죠. 근데 만약 숫자 4개를 동시에 더해야 한다면? 하나씩 4번 도는 대신, 한 방에 4개를 동시에 처리하는 게 NEON입니다. AI 모델의 행렬 연산, 이미지 처리, 오디오 신호처리 — 이 모든 게 결국 '많은 숫자를 동시에' 처리하는 문제고, 그 밑바닥에 이게 있습니다."

### NEON 레지스터의 그림: 하나의 서랍에 여러 칸

- `v0`–`v31` (128비트 벡터 레지스터)
- 하나의 `v` 레지스터를 여러 "레인(lane)"으로 쪼개서 볼 수 있음:
  ```
  v0.4s  →  32비트(s) 값 4개  (4 lanes)
  v0.8h  →  16비트(h) 값 8개  (8 lanes)
  v0.16b →  8비트(b)  값 16개 (16 lanes)
  ```

### 참조로 보여주기 — 개념적 C# 대응 (완전히 같지는 않지만 감을 잡기 위해)

```csharp
// C#에서 벡터 연산의 감각 (System.Numerics.Vector 사용 예)
Vector<int> a = new Vector<int>(new int[] { 1, 2, 3, 4 });
Vector<int> b = new Vector<int>(new int[] { 10, 20, 30, 40 });
Vector<int> result = a + b;   // 4개가 동시에 더해짐
// result = { 11, 22, 33, 44 }
```

> **주의 멘트**: "이건 완벽한 1:1 대응은 아닙니다. C#의 `Vector<T>`는 내부적으로 이 NEON 명령어들을 컴파일러가 대신 골라주는 것뿐이에요. 오늘은 그 '대신 골라주는 일'을 우리 손으로 직접 해봅니다."

### 따라 만들기 — 4개를 동시에 더하기

```asm
.data
.align 4
vec_a: .word 1, 2, 3, 4
vec_b: .word 10, 20, 30, 40

.global _main
.align 4

_main:
    adrp x0, vec_a@PAGE
    add x0, x0, vec_a@PAGEOFF
    adrp x1, vec_b@PAGE
    add x1, x1, vec_b@PAGEOFF

    ld1 {v0.4s}, [x0]        // vec_a 4개를 한 번에 v0에 로드
    ld1 {v1.4s}, [x1]        // vec_b 4개를 한 번에 v1에 로드

    add v2.4s, v0.4s, v1.4s   // 4개 동시 덧셈! -> {11, 22, 33, 44}
    ...
```

### 레인 인덱싱 — 특정 칸 하나만 콕 집기

> "지금 준님이 실전에서 직접 부딪히고 계신 부분이 바로 이겁니다. 벡터 전체가 아니라, 그 안의 특정 레인 하나만 건드리고 싶을 때가 있거든요."

```asm
mov w2, v0.s[0]      // v0의 0번 레인(첫 번째 32비트 값)을 일반 레지스터로 꺼내기
ins v0.s[1], w3        // 일반 레지스터 값을 v0의 1번 레인에 꽂아넣기
dup v3.4s, v0.s[0]     // v0의 0번 레인 값을 4칸 전부에 복제
```

> **실전 회고 멘트**: "이 레인 지정 문법 `.s[0]`, `.h[3]` 같은 것들, 처음엔 저도 계속 헷갈렸습니다. 지금도 Yeoji OS/Hun 어셈블러 작업하면서 이 레인 스펙 관련 제약조건 때문에 계속 씨름 중이에요 — 그래서 이 부분은 '나도 지금 배우는 중'이라는 마음으로 같이 가시면 됩니다. 하하."

### 오늘 세션의 선 긋기

> "NEON은 사실 이 하나로 12시간 강좌를 또 만들 수 있는 주제입니다. 오늘은 '이런 게 존재하고, 왜 필요하고, 기본 문법이 이렇다'까지만 맛보고, 여기서 문을 열어두는 정도로 하겠습니다."

## 세션 3 — lldb로 프레임 까보기, 레지스터 덤프 읽는 법 (55분)

1부, 2부에서 lldb를 살짝씩 써봤다면, 오늘은 **lldb 자체를 제대로 다루는 세션**입니다.

### 참조 먼저 — C# 개발자에게 lldb란

> "C#에서 디버거 켜고 F10, F11로 한 줄씩 밟아나가던 거, 기억하시죠? lldb도 똑같습니다. 다만 눈에 보이는 게 변수 이름이 아니라 레지스터와 메모리 주소라는 것만 다릅니다."

### 브레이크포인트와 스텝 실행

```bash
lldb ./my_program
(lldb) b _main              # _main 함수에 브레이크포인트
(lldb) run
(lldb) next                  # 한 줄씩 (source-level step)
(lldb) stepi                  # 한 명령어씩 (instruction-level step) — 어셈블리엔 이게 진짜
```

### 레지스터 덤프 읽는 법

```bash
(lldb) register read              # 전체 레지스터 한 번에
(lldb) register read x0 x1 x2      # 특정 레지스터만
(lldb) register read -f hex x0      # 16진수로 보기
(lldb) p/x $x0                       # 다른 방식으로 값 확인
```

> **실전 팁**: "레지스터 값이 `0x00000000`인데 뭔가 이상하게 동작한다면, 십중팔구 우리가 원하는 값이 아직 로드되기 전에 읽은 겁니다. 순서를 한 줄 앞뒤로 다시 확인해보세요."

### 프레임과 백트레이스 — 2부 재귀 복습과 연결

```bash
(lldb) bt                    # 전체 콜스택 (2부에서 재귀 깊이 확인할 때 썼던 것)
(lldb) frame select 2          # 특정 프레임으로 이동
(lldb) frame info               # 현재 프레임 상세 정보
```

### 메모리 덤프 — 오늘 배운 로드/스토어와 직결

```bash
(lldb) memory read --size 4 --format x $x0        # x0가 가리키는 주소부터 4바이트씩 읽기
(lldb) x/5xw $x0                                     # 위와 같은 걸 더 짧게 (5개, hex, word)
```

### 종합 실습: 세션 1의 배열 순회 코드를 lldb로 완전히 해부하기

> **라이브 시연 순서**:
> 1. `_loop` 레이블에 브레이크포인트
> 2. `run` → 매 반복마다 `register read x1 x2 x3`로 sum, i, arr[i] 값 변화 관찰
> 3. `memory read --size 4 --format d x0` 로 배열 전체를 메모리에서 직접 읽어서, 우리가 `ldr`로 하나씩 꺼내오던 값들이 실제로 거기 그대로 있다는 걸 확인
> 4. NEON 세션 코드도 다시 로드해서 `register read v0 v1 v2` 로 벡터 레지스터 안에 4개 값이 나란히 들어있는 걸 직접 눈으로 확인

> **클로징 멘트로 연결**: "지금 여러분이 본 이 화면 — 레지스터, 메모리, 벡터 레인 전부 — 이게 여러분이 C#에서 5년, 10년 코딩해도 한 번도 안 열어봤을 자물쇠입니다. 오늘 그 문을 여신 겁니다."
