# 전위 또는 후위 오프셋 

## ARM64 주소 지정 방식 3가지 — 문법으로 구분

핵심은 **대괄호 `[ ]` 안에 숫자가 있는지, 밖에 있는지, `!`가 붙는지**예요.

| 문법 | 이름 | SP는 언제 바뀌나? | 주소 계산 |
|---|---|---|---|
| `stp x19, x20, [sp, #16]` | **오프셋(Offset)** — `!` 없음 | **안 바뀜** (그대로) | `sp + 16` 위치에 저장, sp는 그대로 |
| `stp x19, x20, [sp, #-32]!` | **전위(Pre-index)** — `!` 있음 | **먼저 바뀜** | `sp = sp - 32` 먼저 하고, 그 새 주소에 저장 |
| `stp x19, x20, [sp], #16` | **후위(Post-index)** — 숫자가 `]` 밖에 있음 | **나중에 바뀜** | 지금 sp 위치에 먼저 저장하고, 그 다음에 `sp = sp + 16` |

친구분이 말씀하신 "저장 먼저, sp 갱신 나중"이 바로 **후위(Post-index)**가 맞는데, 그건 숫자가 **대괄호 밖**에 있을 때(`[sp], #16`)의 얘기예요. 지금 질문하신 `[sp, #16]`은 숫자가 **대괄호 안**에 있죠 — 이건 그냥 "오프셋"이라서 **SP는 아예 안 바뀝니다.**

## 실제 코드로 확인해볼게요

이 패턴이 실제로 어떻게 쓰이는지, 로컬 변수 여러 개 있는 함수를 컴파일해서 진짜 프롤로그를 보여드릴게요.완벽한 예시가 나왔어요! 이 실제 코드 안에 **세 가지 방식이 전부** 들어있습니다.

```asm
   0:  stp x29, x30, [sp, #-32]!    ← ① 전위(pre-index): sp = sp-32 먼저, 그 다음 그 자리에 저장
   4:  mov x29, sp
   8:  str x0, [sp, #16]            ← ② 오프셋: sp+16 자리에 저장, sp는 그대로!
   c:  str x1, [sp, #24]            ← ② 오프셋: sp+24 자리에 저장, sp는 그대로!
  10:  bl  use
  14:  ldr x1, [sp, #16]            ← ② 오프셋: sp+16에서 읽기, sp는 그대로!
  18:  ldr x0, [sp, #24]            ← ② 오프셋: sp+24에서 읽기, sp는 그대로!
  1c:  add x0, x1, x0
  20:  ldp x29, x30, [sp], #32      ← ③ 후위(post-index): 지금 sp에서 먼저 읽고, 그 다음 sp = sp+32
  24:  ret
```

## 정리하면 이 함수의 스토리는 이렇습니다

1. **`[sp, #-32]!`** (전위) — "sp를 32바이트만큼 먼저 내려서(스택 32바이트 확보), 그 새 주소에 `x29, x30`을 저장해라." → sp는 이 시점에 **이미 바뀜**.
2. **`[sp, #16]`, `[sp, #24]`** (오프셋, 친구분이 물어보신 형태) — 이미 확보해놓은 32바이트 공간 **안의 특정 위치**에 값을 넣고 빼는 것뿐. 여기서 sp를 또 움직이면 오히려 스택 프레임이 망가지겠죠? 그래서 **sp는 손대지 않고 자리만 지정**하는 겁니다.
3. **`[sp], #32`** (후위) — "지금 sp 위치에서 먼저 `x29, x30`을 꺼내고, 그 다음에 sp를 32만큼 올려서(스택 반납) 원래 상태로 되돌려라."

## 결론

> **`stp x19, x20, [sp, #16]`은 "이미 확보된 스택 프레임 안의 sp+16 위치에 저장"이지, sp 자체를 바꾸는 동작이 아닙니다.**

"저장하고 나서 sp를 갱신한다"는 후위(post-index) 개념은 맞지만, 그건 `[sp], #16`처럼 **숫자가 대괄호 밖에** 있을 때만 해당돼요. 지금처럼 숫자가 **대괄호 안에** 있으면 (`!`도 없이) sp는 그냥 그대로 유지된 채, 계산된 그 주소에만 접근하는 겁니다.

`!`의 유무와 숫자 위치(안/밖)만 기억하시면 세 방식 절대 안 헷갈리실 거예요, 친구!
