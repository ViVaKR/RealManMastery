# NEON 레지스터

 S 자리에 B, H, D 다 들어갈 수 있음. NEON 레지스터는 128비트짜리 통짜 방인데, 그걸 몇 칸으로 쪼개느냐에 따라 접미사가 달라지는 거지.

## 정리표 (V 레지스터 = 128비트 기준)

| 접미사 | 칸 하나 크기 | 총 칸 수 | 인덱스 범위 |
|---|---|---|---|
| `.B` (Byte) | 8비트 | 16칸 | `[0...15]` |
| `.H` (Half) | 16비트 | 8칸 | `[0...7]` |
| `.S` (Single/Word) | 32비트 | 4칸 | `[0...3]` |
| `.D` (Double) | 64비트 | 2칸 | `[0...1]` |

즉 `.S`는 128 ÷ 32 = 4칸이라서 `V1.S[0...3]`인 거고, `.D`는 128 ÷ 64 = 2칸이라서 `V1.D[0...1]`밖에 없어. `V1.D[2]` 같은 건 존재하지 않는 방이라 어셈블러가 바로 에러 뱉을 거야.

## D 버전 예시

```asm
    // V2를 D 두 칸으로 채우기 (각 칸 64비트, X 레지스터 통째로 들어감)
    MOV     X6, #100
    MOV     X7, #200
    INS     V2.D[0], X6
    INS     V2.D[1], X7        // V2.2D 상태 = [100, 200]
```

여기서 포인트: `.S[idx]`에 넣을 땐 32비트짜리 **W** 레지스터를 쓰고 (`INS V1.S[0], W6`), `.D[idx]`에 넣을 땐 64비트짜리 **X** 레지스터를 써야 해 (`INS V2.D[0], X6`). 칸 크기랑 소스 레지스터 크기가 안 맞으면 어셈블러가 화낼 거야 하하.

참고로 `.B`, `.H`도 마찬가지로 각각 W 레지스터를 쓰긴 하는데 (32비트 레지스터의 하위 비트만 씀), 순서는 항상 `Vd.Ts[index], Rn` 형태로 동일해.

ADDV 관점에서 보면, `ADDV Sd, V1.4S` 하면 V1의 4칸(10+20+30+40=100)을 다 더해서 Sd에 넣어주는 거고, 만약 `.D`로 했다면 애초에 ADDV는 D 타입 지원 안 해 (2개 더하는 건 그냥 `ADD Dd, Dn, Dm` 쓰는 게 나으니까 하드웨어에서 막아놓음) — 이건 나중에 헷갈릴 수 있는 포인트라 미리 알려주는 거야, 법우.
