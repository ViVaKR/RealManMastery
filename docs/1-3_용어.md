# 핵심 용어 6종

## 📚 Apple Silicon ARM64 강좌용 핵심 용어 사전

### 1. ABI (Application Binary Interface)

* 무슨 뜻인가요?: 애플리케이션 이진 인터페이스의 약자입니다.
* 쉽게 말해서: 소스 코드가 컴파일되어 0과 1로 이루어진 ‘기계어(Binary)’ 상태가 되었을 때, 프로그램들이 서로 소통하고 실행되기 위한 "최종 규칙판"입니다.
* 포인트: "컴퓨터 세계의 도로 교통 법규"라고 설명하시면 좋습니다. "함수를 부를 때 데이터는 어떤 레지스터에 담아 보낼지", "메모리 스택은 어떻게 쌓을지" 등을 엄격하게 약속해 둔 것입니다. Apple은 이 규칙을 AAPCS64(ARM Architecture Procedure Call Standard)를 기반으로 직접 커스텀해서 사용합니다.

## 2. 레지스터 (Registers)

* 무슨 뜻인가요?: CPU 내부에 존재하는 초고속 임시 저장소입니다.
* 쉽게 말해서: CPU가 연산할 때 책상 위에 올려두고 쓰는 '포스트잇'이나 '메모장' 같은 것입니다. 메모리(RAM)에서 데이터를 가져오는 건 느리기 때문에, 모든 계산은 이 레지스터에 값을 올려두고 처리합니다.
* 강의 포인트: ARM64에는 기본적으로 X0부터 X31까지 32개의 64비트 레지스터가 있다는 점을 짚어줍니다. (32비트 연산 때는 W0~W31로 부릅니다.)

## 3. AAPCS64 (ARM 64-bit Procedure Call Standard)

* ARM64의 함수 **호출 규약**
* 함수를 만들고 사용할 때 지켜야 하는 **레지스터 사용 설명서**입니다.
* 32개의 레지스터를 사용하는 규칙.

* X0 ~ X7: 함수에 넘겨줄 인자(파라미터)나 결과 값을 담는 곳.
* x8 : 간접 결과의 주소전달, 반환값이 128보다 크면 반환값 포인터 그렇지 않으면 임시 레지스터에 기록
* X9 ~ X15: 함수 안에서 마음대로 쓰고 버려도 되는 임시 공간 (Caller-saved).
* X19 ~ X28: 함수가 끝나도 원래 값을 보존해 줘야 하는 중요한 공간 (Callee-saved).
* x29 : 프레임 포인터, fp
* x30 : 링크 레지스터, lr
* sp : 스택포인터

## 4. LR (Link Register / X30) & PC (Program Counter)

* 돌아갈 주소를 기억하는 레지스터(LR)와 
* 현재 실행 중인 주소를 가리키는 레지스터(PC)입니다.
* PC: 책을 읽을 때 현재 내 눈이 머무는 '손가락 끝' 다음 실행할 명령어의 주소를 가리킵니다.
* LR: 원래 읽던 책 페이지에 끼워두는 '책갈피'입니다. 함수가 끝나고 원래 자리로 돌아올 주소를 저장합니다.

## 5. SP (Stack Pointer) & FP (Frame Pointer / X29)

* 메모리의 스택 영역을 관리하는 레지스터들입니다.
* 함수가 실행될 때 필요한 지역 변수나 임시 데이터는 메모리의 '스택(Stack)'이라는 상자에 차곡차곡 쌓입니다.
* SP: 현재 상자가 어디까지 쌓였는지 알려주는 '맨 꼭대기 위치 수치'입니다.
* FP: 현재 함수가 시작된 '상자의 바닥 기준점'입니다. 디버깅할 때 미로를 찾아가는 실타래 역할을 합니다.

## 6. NZCV (Condition Flags / 상태 플래그)

* 연산 결과의 상태를 나타내는 4가지 깃발입니다.
* if문이나 for문 같은 조건문을 실행할 때, 
* CPU가 직전 계산 결과를 바탕으로 올리는 깃발입니다.
* N (Negative): 결과가 음수다! 🚩
* Z (Zero): 결과가 0이다! (두 값이 같을 때 빼면 0이 되므로, 비교할 때 주로 쓰임) 🚩
* C (Carry): 자리 올림이나 빌림이 발생했다! 🚩
* V (Overflow): 계산 용량이 넘쳐서 에러가 났다! 🚩
