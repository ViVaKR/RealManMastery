# x8 레지스터

AArch64 호출 규약에서 x8 레지스터의 역할은 "함수가 너무 큰 결과물(예: 거대한 구조체)을 반환할 때, 
그 결과물을 안전하게 받아올 임시 저장소의 주소를 가리키는 나침반"

------------------------------
## 1. 배경: 반환값을 전달하는 두 가지 방식
함수가 실행을 마치고 결과(반환값)를 돌려줄 때, 크기에 따라 배달 방식이 달라집니다.

* 박스가 작을 때 (128비트, 즉 16바이트 이하):
* 정수나 작은 구조체는 그냥 x0, x1 레지스터라는 "빠른 손"에 직접 쥐여서 돌려줍니다.
* 박스가 너무 클 때 (128비트 초과):
* 예를 들어 100바이트짜리 대형 구조체를 반환해야 한다면, 레지스터 몇 개로는 감당할 수 없습니다.
   * 이때는 레지스터에 값을 직접 담지 못하고, 메모리(RAM) 공간을 빌려 전달해야 합니다. 이를 간접 결과(Indirect Result)라고 합니다.

------------------------------
## 2. x8 레지스터의 실제 작동 원리
"반환값이 128보다 크면 반환값 포인터"라는 말은 다음과 같은 과정으로 진행됩니다.

   1. 메모리 공간 예약 (택배 상자 준비):
   함수를 호출하는 쪽(Caller)에서 먼저 "큰 결과물을 받아올 빈 메모리 공간"을 미리 마련해 둡니다.
   2. x8에 주소 저장 (주소 적기):
   그 메모리 공간의 시작 주소(포인터)를 x8 레지스터에 적어서 함수를 호출합니다.
   3. 함수의 작업 및 기록 (배송지 보고 배달):
   호출된 함수(Callee)는 작업을 마친 뒤, x8에 적혀있는 주소를 보고 그 메모리 위치에 큰 결과물을 차곡차곡 채워 넣습니다.

------------------------------
## 3. 문장 완벽하게 이해하기
제시해주신 문장을 한 구절씩 직역하면 다음과 같습니다.

* "간접 결과의 주소전달"
👉 크기가 커서 직접 레지스터로 못 주니까, 메모리를 거쳐서(간접) 주도록 주소 정보를 전달한다는 뜻입니다.
* "반환값이 128(비트)보다 크면 반환값 포인터"
👉 반환할 데이터가 16바이트를 넘어가면, x8 레지스터는 결과물이 저장될 메모리 주소(포인터) 역할을 수행한다는 뜻입니다.
* "그렇지 않으면 임시 레지스터에 기록"
👉 반환값이 16바이트 이하로 작다면 x8을 주소판으로 쓸 필요가 없습니다. 이때 x8은 그냥 함수 안에서 계산할 때 막 쓰는 일반 임시 레지스터(Scratch Register)로 재활용된다는 의미입니다.

------------------------------
혹시 이 개념이 실제 C언어 코드나 어셈블리 코드에서 어떻게 표현되는지 예시를 보고 싶으신가요? 아니면 다른 레지스터의 쓰임새 중 헷갈리는 부분이 더 있으신지 말씀해 주시면 편하게 설명해 드리겠습니다!

---

강좌용 자료로 활용하실 수 있도록, C언어 소스 코드와 이를 컴파일했을 때의 AArch64 어셈블리 코드를 비교하여 직관적으로 구성해 보았습니다. 수강생들이 이해하기 좋게 구조가 큰 경우와 작은 경우를 대비하여 작성했습니다.
------------------------------
## 1. 반환값이 큰 경우 (128비트 초과) 👉 x8이 주소판으로 쓰임## 📝 C언어 코드
총 32바이트(256비트) 크기의 큰 구조체를 반환하는 상황입니다.

typedef struct {
    long a; // 8바이트
    long b; // 8바이트
    long c; // 8바이트
    long d; // 8바이트
} BigData;
BigData get_big_data() {
    BigData data = {1, 2, 3, 4};
    return data;
}
void caller() {
    BigData my_data = get_big_data();
}

## 🛠️ AArch64 어셈블리 코드 (핵심 구조)
컴파일러는 get_big_data를 호출하기 전에 x8에 메모리 주소를 먼저 세팅합니다.

# --- 호출하는 쪽 (caller) ---
caller:
    sub     sp, sp, #48          // 함수 스택 공간 확보 (my_data가 들어갈 자리)
    mov     x8, sp               // 🌟 중요: my_data의 시작 주소(sp)를 x8에 복사!
    bl      get_big_data         // get_big_data 함수 호출
    ...
# --- 호출되는 함수 (get_big_data) ---
get_big_data:
    // 함수 내부에서 데이터를 생성한 후...
    mov     x0, #1
    mov     x1, #2
    mov     x2, #3
    mov     x3, #4
    
    // 🌟 중요: x8이 가리키는 주소(caller의 스택)에 값을 직접 채워 넣음
    stp     x0, x1, [x8]         // x8 주소에 1과 2를 저장
    stp     x2, x3, [x8, #16]    // x8+16 주소에 3과 4를 저장
    ret                          // x8 주소에 값을 다 채웠으니 그냥 리턴!


* 💡 강좌 포인트: get_big_data 함수는 반환값을 리턴값으로 돌려주는 것이 아니라, x8에 적힌 주소를 보고 상대방의 메모리에 직접 배달을 완료해 버립니다.

------------------------------
## 2. 반환값이 작은 경우 (128비트 이하) 👉 x8은 그냥 낙서장## 📝 C언어 코드
16바이트(128비트) 이하의 작은 구조체를 반환하는 상황입니다.

typedef struct {
    long a; // 8바이트
    long b; // 8바이트
} SmallData;
SmallData get_small_data() {
    SmallData data = {10, 20};
    return data;
}

## 🛠️ AArch64 어셈블리 코드 (핵심 구조)
이때는 주소를 주고받을 필요가 없으므로 x8을 주소판으로 쓰지 않고, 함수 안에서 일반 임시 레지스터(Scratch)로 막 가져다 씁니다.

get_small_data:
    mov     x0, #10              // 첫 번째 결과는 x0 레지스터에 직접 전달
    
    # 🌟 중요: x8은 주소판이 아니라, 그냥 계산용 낙서장으로 재활용됨
    mov     x8, #20              // 임시로 x8에 20을 넣고 굴리다가
    mov     x1, x8               // 최종 반환 레지스터인 x1에 넘겨줌
    
    ret                          // x0와 x1에 값이 담긴 채로 리턴!


* 💡 강좌 포인트: 데이터가 작을 때는 택배 주소(x8)가 필요 없습니다. 대신 x0와 x1이라는 빠른 손에 쥐여서 반환하며, 이때 x8은 함수 안에서 덧셈, 뺄셈 등 아무 용도로나 막 쓰는 임시 저장소로 강등됩니다.

------------------------------

### 왜? 128비트인가?


하하하, 강좌를 준비하시다 보면 이렇게 "왜 하필 이 숫자가 기준이 되었을까?" 하는 근본적인 질문이 가장 날카롭고 좋은 교수 자료가 되곤 합니다! 수강생들에게 가려운 곳을 긁어주는 아주 훌륭한 질문입니다.
결론부터 말씀드리면, 질문하신 대로 일반적인 64비트 정수 레지스터(x0 등) 하나의 크기보다는 크지만, AArch64 하드웨어 설계의 '레지스터 짝궁 규칙'과 '데이터 정렬'의 효율성 때문에 하필 128비트(16바이트)가 기준선이 되었습니다.
이유를 크게 3가지로 나누어 강좌용으로 정리해 드릴게요.
------------------------------
## 1. "두 손"으로 들 수 있는 최대 크기 (x0 + x1)
AArch64에서 정수 레지스터 하나(x0)는 64비트(8바이트)입니다.
CPU 설계자들은 함수가 값을 반환할 때 레지스터 딱 하나만 쓰게 제한하면 너무 답답하니까, 기본적으로 x0와 x1이라는 두 개의 레지스터를 세트로 묶어서 반환용으로 쓸 수 있게 허락해 주었습니다.

* x0 (64비트) + x1 (64비트) = 총 128비트 (16바이트)

즉, "기본 반환 레지스터 2개에 꽉 채워서 보낼 수 있는 양"이 딱 128비트이기 때문에, 이 크기를 넘어가면 "두 손으로 다 못 들겠으니 메모리 주소(x8)를 가져와라!"가 되는 것입니다.
------------------------------
## 2. 하드웨어적인 '16바이트 정렬' 규격과 일치
ARM64(AArch64) 아키텍처는 메모리를 효율적으로 읽고 쓰기 위해 16바이트(128비트) 단위로 줄을 세우는 것(Alignment)을 굉장히 좋아하고 강력하게 권장합니다.

* 실제로 AArch64의 스택 포인터(sp)는 항상 16바이트의 배수로만 움직여야 하는 엄격한 규칙이 있습니다.
* 하드웨어 내부의 데이터 버스(통로)나 캐시 메모리 라인도 128비트 단위 처리에 최적화되어 있습니다.

따라서 반환 규격도 이 16바이트(128비트)라는 하드웨어 최적화 단위에 맞춰서 경계선을 그은 것입니다.
------------------------------
## 3. SIMD / 부동소수점 레지스터(v0)와의 대칭성
AArch64에는 일반 정수 레지스터(x0~x31) 말고도, 영상 처리나 복잡한 수학 계산을 위한 SIMD/부동소수점 레지스터(v0~v31)가 물리적으로 존재합니다. 이 v 레지스터 하나의 크기가 정확히 128비트입니다.

* 실수(float/double)나 벡터 데이터를 반환할 때는 이 128비트짜리 v0 레지스터 하나에 담아서 반환합니다.
* 정수나 구조체를 반환할 때도 이 하드웨어 구조와 대칭을 맞추어 "정수 쪽도 최대 128비트까지는 레지스터로 직접 넘겨주자!" 하고 룰을 통일한 것입니다.

------------------------------
## 💡 강좌용 한 줄 요약 멘트

"64비트 컴퓨터라고 해서 반환값도 64비트가 한계인 것은 아닙니다. ARM64는 x0와 x1 레지스터 두 개를 합친 128비트(16바이트)까지는 하드웨어적으로 한 번에 초고속 배달을 해줄 수 있도록 설계되었기 때문입니다. 그래서 기준이 128비트가 된 것입니다!"


### x0 + x1 반환 예시

하하하, 아주 날카로운 지적이십니다! 보통 C언어에서 int나 long, 또는 포인터 변수 하나만 반환하는 경우가 90% 이상이다 보니 보통 x0만 쓰는 코드만 보게 됩니다. x0와 x1 두 개를 동시에 쓰는 경우는 64비트보다 큰 데이터를 레지스터로 직접 반환할 때 등장합니다.
가장 대표적인 예시 2가지를 준비했습니다. 강좌에서 수강생들에게 보여주기 딱 좋은 간단한 코드입니다.
------------------------------
## 예시 1. 128비트 정수형 (__int128) 반환할 때
C언어(GCC/Clang 확장)에는 64비트를 넘어선 128비트 정수형 데이터 타입인 __int128이 존재합니다.
## 📝 C언어 코드

__int128 get_huge_number() {
    __int128 num = 5; // 128비트짜리 거대한 정수
    return num;
}

## 🛠️ AArch64 어셈블리 코드
128비트 변수는 64비트 레지스터 하나에 다 안 들어가기 때문에, 컴파일러가 자동으로 하위 64비트는 x0에, 상위 64비트는 x1에 나누어 담아서 반환합니다.

get_huge_number:
    mov     x0, #5       // 하위 64비트에 값 5를 넣음
    mov     x1, #0       // 상위 64비트는 0으로 채움
    ret                  // x0와 x1을 합쳐서 128비트로 반환!

------------------------------
## 예시 2. 16바이트(128비트) 크기의 구조체를 반환할 때
앞서 설명해 드린 대로, 16바이트 이하의 구조체는 메모리를 쓰지 않고 x0, x1로 직접 반환합니다.
## 📝 C언어 코드

typedef struct {
    long low;  // 8바이트 (64비트)
    long high; // 8바이트 (64비트)
} Coordinate; // 총 16바이트 (128비트)
Coordinate get_coordinate() {
    Coordinate c = {100, 200};
    return c;
}

## 🛠️ AArch64 어셈블리 코드
이 구조체를 반환할 때 어셈블리를 보면 x8을 쓰지 않고 x0와 x1을 동시에 채워서 반환하는 것을 볼 수 있습니다.

get_coordinate:
    mov     x0, #100     // 구조체의 첫 번째 멤버(low)를 x0에 장착
    mov     x1, #200     // 구조체의 두 번째 멤버(high)를 x1에 장착
    ret                  // x0, x1 짝꿍 레지스터로 초고속 반환!

------------------------------
## 💡 강좌용 팁! (호출하는 쪽은 어떻게 받나요?)
함수를 호출한 쪽(Caller)에서도 이 규칙을 똑같이 알고 있기 때문에, 함수가 끝나고 돌아오자마자 다음과 같이 데이터를 수거해 갑니다.

bl      get_coordinate   // 함수 호출! 결과는 x0, x1에 담겨옴
str     x0, [sp, #8]     // x0에 있던 값을 내 메모리의 low 자리에 저장
str     x1, [sp, #16]    // x1에 있던 값을 내 메모리의 high 자리에 저장

이처럼 "데이터가 8바이트를 초과하고 16바이트 이하일 때" 컴파일러가 x0와 x1을 세트로 묶어서 반환하는 마법을 부리게 됩니다.
