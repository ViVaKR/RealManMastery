```c
(lldb) f 1
frame #1: 0x000000018e1b44e4 dyld`start + 6992
dyld`start:
->  0x18e1b44e4 <+6992>: mov    x19, x0
    0x18e1b44e8 <+6996>: ldr    x8, [sp, #0x1d0]
    0x18e1b44ec <+7000>: ldr    x8, [x8, #0x8]
    0x18e1b44f0 <+7004>: add    x0, x8, #0x70

// PC (화살표) 는 "다음에 실행될 명령어" 를 가리킨다 = 그 줄은 아직 실행전 
// --> CPU 가 명령어를 fetch(가져오기) -> decode(해석) -> execute(실행)
// --> PC 는 항상 "fetch 할 대상" 을 미리 가리키고 있기 때문 
// --> si (step instruction) 를 한 번 치면 화살표가 한 줄 아래로 내려 가면서
//                           방금 그 줄이 실행 완료된 상태로 바뀜


// [ 정리 ] 
// "_main 실행 끝났네"
// "자 아까 나온 리턴값(x0) 을 x19에 잘 챙겨 두고"
// "OS 정리 작업 함수에 넘겨줄 구조체 주소 계산해서 디버거/OS 후속 처리하려 가자!"
(lldb) disassemble --pc
dyld`start:
->  0x18e1b44e4 <+6992>: mov    x19, x0
    0x18e1b44e8 <+6996>: ldr    x8, [sp, #0x1d0]
    0x18e1b44ec <+7000>: ldr    x8, [x8, #0x8]
    0x18e1b44f0 <+7004>: add    x0, x8, #0x70
(lldb) 

// 1. `mov x19, x0` : _main 함수가 반환한 최종 리턴값(x0) 을 백업용 x19로 복사
// --> _main 에서 mov x0, #0 으로 리턴값을 0으로 맞춰서 나왔기 때문에, 현재 x0 에 있던 0이  x19에 저장 됩니다. 

// 2. `ldr x8, [sp, #0x1d0]` :  스택 메모리의 특정 위 에서 메모리 주소 포인터를 읽어와 x8 레지스터에 넣음

// 3. `ldr x8, [x8, #0x8]` : 방금 가져온 구조체 주소(x8) 에서 8바이트 떨어진 위치의 매부 포인터를 다시 읽어와 x8을 갱신 함
// --> 포인터를 두 번 타고 들어가는 간법 참조(Pointer Chaining) 로 , 내부 데이터 구조체의 특정 멤버 변수에 접근하는 전형적인 C/C++ 객체 탐색 패턴 

// 4. `add x0, x8, #0x70` : x8 주소값에 0x70(112바이트)을 더해 최종 인자 주소를 만든뒤, 이를 첫번째 파라미터 레지스터인 x0 에 담습니다.
// --> 다음에 이어질 dyld 내부 청소/종료 함수에 넘겨줄 데이터 구조체의 오프셋 주소를 준비하는 과정
```
